# `crates/core` — `jellysink-core`

- `config/` — `paths.rs` (`Paths`: the config dir and every file in it, plus the cache dir jellytui's covers live in), `settings.rs` (`Config` — config.toml — and `Field`, the exhaustive list of user-facing keys), `mpv_args.rs` (`MpvArgs`, mpv_args.conf, re-read on every mpv spawn), `credentials.rs` (`Credentials`, cred.json, mode 0600), `server.rs` (`normalize_server_url` — bare host → `http://host`, no port is ever invented — and `device_name`). `atomic_write` and `read_optional` (a missing file is `None`) live in `mod.rs`, where all three files reach them — and jellytui's cover cache, which needs the same tmp-and-rename for the same reason. `Field::read`/`Field::write` are the whole `config get`/`set` interface, `mpv_args` included.
- `logging.rs` — `init_tracing`; the filter is `RUST_LOG` or `info`, and it is an `EnvFilter`, so the full `target[span{field}]=level` syntax works — `Targets` would drop the `regex` dependency and is deliberately not used. There is no `log_level` config key: the environment variable every Rust user already knows is the whole interface. `log_filter` is `pub` because `jellytui` builds its own subscriber (`crates/jellytui/src/logs.rs`); `init_tracing` itself stays daemon-only, because it writes to stdout and would paint over the alternate screen.
- `cast.rs` — `CastEvent`: the Jellyfin remote-control commands (PlayNow/Pause/Seek/…) parsed from WebSocket messages. Parsing only. In core because `jellyfin/session.rs` parses into it and `remote_test.rs` holds jellytui's `play_now` to the same parser.
- `jellyfin/` — server API: `auth.rs` (login, `Api` client, cached auth header, `AuthExpired`, and the transport helpers: every one but `get` and `post_json_unchecked` turns a non-success status into an error naming the method and URL), `browse.rs` (the listing endpoints — `user_views`, `items` + the `ItemQuery` builder, `seasons`, `episodes`/`episodes_all`, `next_up`, `resume`, `get_item`, and `with_legacy_fallback` for the endpoints pre-10.9 servers only have under `/Users/{id}/…`), `played.rs` (`set_played`, the watched toggle), `remote.rs` (driving *another* session: `session_for_device` and `play_now`, which is all jellytui sends — playback control is mpv's, see `specs/tui.md`; note `session.rs` is the WebSocket and `remote.rs` is remote control, they are not the same thing), `model.rs` (the typed `Item`/`UserData`/`Session`/`PlayState` DTOs the frontend renders; the playback path still works in `Value` because it forwards rather than displays), `session.rs` (WebSocket URL + message parsing), `url.rs` (stream and image URLs, `redact_api_key`, and `encode_query_value`), and `integration_test.rs` (all of the above against the live test server, see the root `CLAUDE.md`). The MPRIS image URL carries no token: the image endpoint is anonymous, and the URL leaves the process over D-Bus and `stop.sock`.
- `status.rs` — `PlayerStatus` / `NowPlaying`, the wire format of `jellysink status` and of jellytui's once-a-second footer poll. Serialized by the daemon, deserialized by both clients, so it belongs to neither.
- `update.rs` — the one GitHub-release self-updater, parameterised by binary name so either binary can be checked, installed in place, or installed beside the running one. `install_both` is the whole `update` subcommand — both binaries and then the daemon's restart — so `jellysink update` and `jellytui update` are one flow. The `println!`s here are that subcommand's output; `update.rs` and `exit_on_usage_error` are the only code in core that prints. See `specs/tui.md`.
- `instance.rs` — the single-instance lock and the `stop.sock` client: `stop`, `restart` (any update path) and `status`. One attempt each; a socket with nothing behind it is "not running" and a listener that does not answer within `STATUS_REPLY_TIMEOUT` (under the 1 Hz poll interval) is "not responding" (`specs/session.md`). The listener that answers them is the daemon's.
- `ticks.rs` — Jellyfin position ticks (100 ns units) ↔ seconds, plus `format_hms` for anything that prints a position. Nothing to do with media.
- `json.rs` — the lenient coercions Jellyfin's WebSocket payloads need: some tick fields arrive quoted, and a one-id list arrives as a bare string. Crate-private; mpv's strict property readers in `mpv/ipc.rs` are the deliberate opposite and stay there.
- `error.rs` — `usage_err`, and `exit_on_usage_error`, which both `main`s wrap their result in.
